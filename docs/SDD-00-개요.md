# SDD-00. 개요 — PMF Editor

- 버전 0.1 · 2026-09-03
- 상태: **설계 확정. 구현 0.**
- 대상 게임: `G:\Project\Prowl's Moving Factory` (Unity 6000.5.7f1 · 호위형 타워 디펜스 · 그레이박스 프로토타입)
- 이 문서 묶음의 이름: **SDD** (Software Design Document). `SDD-00` ~ `SDD-07` + `adr/ADR-E*`.

> **이 문서가 존재하는 이유.** 사용자 요구는 "결과물(코드)에 *왜 이렇게 설계했는가* 가 주석으로 잘 표현되어야 한다" 이다.
> 주석은 어딘가에서 베껴 와야 한다. 그 원천이 이 SDD 다. 그래서 여기 적히는 모든 결정은 **결정 + 이유 + 대가** 를 함께 갖고,
> 절마다 안정 ID(`[D-<문서>-<일련>]` 형식)를 붙여 코드가 그 ID 로 되돌아올 수 있게 한다 (→ §6 주석 규약).

## 1. 한 문장

> **기획자가 브라우저에서 게임 화면과 같은 그림으로 스테이지를 그리고, `.toon` 파일 하나로 Unity 에 넘긴다.**

## 2. 왜 만드는가 `[D-00-01]`

게임의 맵은 지금 **C# 코드에 하드코딩**되어 있다 (`Assets/_Project/Scripts/Editor/GreyboxMapData.cs`).
씬 재생성(`PMF/Create Greybox Scene`)이 그 코드로 타일을 다시 칠하므로, 손으로 그린 것은 **재생성 한 번에 전부 사라진다** —
이 프로젝트에서 이미 두 번 사고가 났다 (게임 Serena 메모리 `scene_rebuild_wipes_handwork`).

기획자는 Unity 를 쓰지 않는다. 텍스트 파일을 직접 편집하는 1차 계획(CSV/JSON)은 "격자를 텍스트로 손으로 맞추는" 일이라 폐기했다
(게임 `.docs/PLAN-authoring-pipeline.md` §0). 기획자가 원하는 것은 *파일 편집* 이 아니라 **보면서 칠하는 것** 이다.

그래서 이 툴의 한 줄 요약은 게임 쪽 계획과 같다: **파괴 경로를 반영 경로로 바꾼다.**
원본이 코드(`GreyboxMapData.cs`)에서 파일(`Stage_X.toon`)로 옮겨가면, 같은 재생성 명령이 기획자 작업을 지우는 대신 반영한다.

## 6. 주석 규약 — "왜" 를 코드에 남기는 방법 `[D-00-05]`

사용자 요구의 핵심이다. 문화에 맡기지 않고 **게이트** 로 만든다.

### 6-1. 파일 헤더 (모든 `src/**/*.ts`, 게임 쪽 `Authoring/*.cs` 도 동일)

```ts
/**
 * 목적: 이 파일이 하는 일 한 줄.
 * 왜 이 구조인가: 다른 방법 대신 이렇게 한 이유. 두세 줄.
 * 바꾸면 안 되는 것: 여기 있는 불변식. 어기면 무엇이 깨지는지.
 * 근거: SDD-02 §4 [D-02-07], ADR-E06
 */
```

- `근거:` 줄에는 반드시 **SDD 절 ID 나 ADR 번호** 가 하나 이상 있어야 한다.
- vitest 에 `header-gate.test.ts` 를 두어 헤더 4항목이 없는 파일은 **테스트 실패** 로 잡는다 (→ SDD-06 §4).

### 6-2. 줄 주석

- 비자명한 판단이 있는 줄은 `// 왜:` 로 시작하는 주석을 단다. 무엇을 하는지가 아니라 **왜 그렇게 하는지** 를 쓴다.
- 게임 코드에서 옮겨온 값·수식은 `// 출처: SceneParts.cs:41-55` 처럼 **파일:라인** 을 쓴다. 게임 코드가 바뀌면 이 주석을 따라가 고친다.
- 지키지 않은 사양·의도적 편차는 `// 편차:` 로 시작한다 (예: TOON 인코더가 주석을 내는 것 → ADR-E02).

### 6-3. SDD 절 ID

- 형식 `[D-<문서번호>-<일련>]`. 예: `[D-02-07]` = SDD-02 의 7번째 결정.
- ID 는 **한 번 붙이면 바꾸지 않는다.** 절을 지우면 ID 를 "폐기" 로 남긴다. 코드가 참조하고 있기 때문이다.

## 7. 용어 `[D-00-06]`

게임 용어는 게임 `GDD.md` §2 를 그대로 쓴다. **동의어를 새로 짓지 않는다.**

| 한글 | 식별자 | 뜻 (툴 관점) |
|---|---|---|
| 보호대상 | `Escortee` | `start` 노드에서 출발해 `exit` 노드로 가는 개체. 판의 시계 |
| 모체 | `Mother` (`MotherSpawner`) | 보호대상을 뒤쫓으며 적을 뱉는 스폰 지점. 같은 `start` 에서 출발 |
| 잡몹 | `Enemy` | `spawn.table` 의 `EnemyDefinition` 이름으로 참조 |
| 마을 | `Village` | `V` 셀. 아군 고용 출발점 |
| 배치 슬롯 | `Buildable` 셀 | 아군을 놓을 수 있는 유일한 셀 종류 |
| 경로 그래프 | `PathGraph` | 노드 + 방향 엣지 + 통행 권한 |
| 지름길 | `shortcut` 엣지 | `allowed = Escortee`, 초기 닫힘 |
| 버스트 | `burst` | 보호대상이 트리거 노드를 지나면 모체가 멈추고 밀도를 올림. 총량 보존 |
| 스테이지 | `Stage` | `.toon` 파일 하나 = 스테이지 하나 |

툴 전용 용어:

| 용어 | 뜻 |
|---|---|
| 문서 (`StageDocument`) | 메모리 안의 스테이지 전체. 파일의 1:1 대응물 |
| 커맨드 (`Command`) | 문서를 바꾸는 유일한 수단. `do`/`undo` 쌍 |
| 레이어 | 화면 표시 단위 (타일·경로·오브젝트·오버레이·시뮬). **파일 구조가 아니다** |
| 오브젝트 계층 | "선택할 수 있는 것" 의 집합 — 마을·시작·탈출·트리거 노드. UI 개념 |
| 팔레트 | 셀 7종 + 지우개 |
| 씨앗 | 현재 게임 맵을 그대로 옮긴 `examples/Stage_Greybox.toon`. 빈 화면에서 시작하지 않게 |
