# SDD-07. 로드맵 — M0 ~ M6

- 버전 0.1 · 2026-09-03
- 원칙: 각 마일스톤이 **그 자체로 쓸모 있고**, 앞 단계를 되돌리지 않는다. 위험이 낮은 순서다. **M4 까지 Unity 프로젝트를 한 줄도 건드리지 않는다.**

---

## M0. 골격 `[D-07-01]`

- `npm create vite` (vanilla-ts) + `vite-plugin-singlefile` + vitest. `tsconfig` strict.
- 폴더 `src/core src/ui src/io`, 빈 `main.ts` 가 "Hello" 캔버스를 그린다.
- 게이트 테스트 4개 (SDD-06 §4) — **코드보다 먼저.** 첫 파일부터 헤더를 강제한다.
- `CLAUDE.md` (에디터 프로젝트) · `.serena/project.yml` `language: typescript` · `.gitignore` · `git init`.
- **DoD:** `npm test` 통과, `npm run build` 가 `dist/pmf-editor.html` 하나를 낸다. 더블클릭으로 열린다.

## M1. 코어 — 모델·코덱·검증·씨앗 왕복 `[D-07-02]`

- `core/model` `core/toon`(encode/decode) `core/validate`(규칙 전부 + ID 목록) `core/geometry`(Bresenham·플러드필·다익스트라).
- `docs/fixtures/` 전부 (규칙 ID 당 하나 + minimal + valid).
- 골든: 씨앗 왕복 바이트 동일, 셀 통계, 도달 영역 205/178 (SDD-06 §2).
- **DoD:** SDD-06 §2 표의 시뮬 제외 전부 통과. 브라우저는 아직 아무것도 안 보여 줘도 된다.

## M2. 맵 편집 UI `[D-07-03]`

- 레이어 캔버스·뷰 변환·줌·팬·격자·좌표 눈금·미니맵.
- 팔레트, 브러시(1·3·5, Shift 직선), 선, 사각, 채우기, 선택/복사/붙여넣기, 스포이드. 전부 커맨드. Undo/Redo.
- 도달 영역 레이어 + 상태줄. 검증 마커(맵 규칙만).
- 파일 IO (FSAA + 폴백), TOON 복사, 초안 복구, 씨앗 내장.
- **첫 배포**: VPS Caddy 에 정적 사이트 블록 + `npm run deploy` (SDD-01 §9, ADR-E01). 서브도메인은 이때 정한다.
- **DoD:** SDD-06 §6 M2 조건. 기획자에게 **처음 보여 주는 시점** (URL 로) — 여기서 받은 피드백으로 SDD-03 개정.

## M3. 경로·오브젝트·스폰·밸런스 `[D-07-04]`

- 노드/엣지 도구, 오브젝트 선택과 속성 패널, `RenameNode` 참조 갱신, 맵 크기 변경 다이얼로그.
- 하단 탭 4개 (맵·경로·스폰·밸런스) 폼과 표, 파생값 표시, 카탈로그.
- 검증 패널 완성 (규칙 전부, 클릭 포커스), 저장 시 오류 주석.
- **DoD:** 스테이지 하나를 툴만으로 처음부터 끝까지 만들 수 있다. SDD-06 §6 M3.

## M4. 시뮬레이션 미리보기 `[D-07-05]`

- `core/sim` (SDD-04 §3) + 회귀 테스트 (119 / 56 / 402).
- **첫 작업: `MotherSpawner.cs` 를 읽고 Idle 중 스폰 여부 등 가정을 확정** (SDD-04 §3-3). 어긋나면 SDD-04 를 먼저 고친다.
- 타임라인 패널, 재생, 파라미터(시드·지름길 개방 시각).
- 도달 영역 4-연결 가정을 `AllyUnit.CanReach` 와 대조 (게임 에디터에서 eval 로 씨앗 맵 전수 비교).
- **DoD:** SDD-06 §6 M4.

## M5. Unity 임포터·익스포터 `[D-07-06]` — ⚠️ 가장 위험한 단계

- 게임 프로젝트에 SDD-05 §2 파일들. EditMode 테스트 (SDD-05 §11).
- 순서: (1) `MapDefinition`/`PathDefinition` SO + Exporter → **씨앗을 게임에서 뽑아 `docs/examples/Stage_Greybox.toon` 과 바이트 비교** (다르면 어느 쪽이 틀렸는지 조사, 대개 문서 쪽 오타) → (2) Reader·Validator·픽스처 테스트 → (3) Importer + 창 → (4) `SceneParts` 연결 (폴백 유지) → (5) 씬 재생성 → 플레이 확인 → (6) 총수입 천장 재측정.
- 왜 익스포터가 먼저인가: 임포터를 먼저 만들면 검증할 파일이 손으로 쓴 것뿐이다. 익스포터가 뽑은 파일이 씨앗과 같으면 두 구현(TS·C#)이 같은 계약을 보고 있다는 증거다.
- **DoD:** 툴에서 고친 `.toon` → 임포트 → 씬 재생성 → 바뀐 맵·경로·스폰으로 플레이. EditMode 전체 통과. 콘솔 경고 0. `GreyboxMapData.cs` 삭제는 이 DoD 통과 **후 한 사이클 더 두고** (다음 마일스톤 시작 때).

## M6. 기획자 왕복 `[D-07-07]` (사람 필요)

- 기획자에게 **URL** (정적 호스팅) + 씨앗 `.toon` 을 zip 으로 전달. 돌려받는 것도 zip/메일 (2026-09-03 확정).
- 설명서 없이 스테이지 하나 수정 → 돌려받아 임포트 → 플레이.
- 막힌 지점 기록 → SDD-03 개정 → 다시.
- **DoD:** 개발자 도움 없이 한 바퀴.

## 후속 (범위 밖, 기록만) `[D-07-08]`

- 여러 스테이지 파일 관리 UI (탭), 최근 파일.
- 색상을 데이터로 빼기 (ADR-E09 미결).
- `pmf.units/1` — 병종 수치 파일과 툴 탭.
- 밸런스 상담용 프롬프트 템플릿 (TOON 복사 + 질문 틀).
- 서버 저장 API (PHP, 상주 프로세스 없이) — M6 뒤 zip 왕복이 병목이면 (ADR-E01 보류 안 B).
- `GridSystem` 이 타일맵 대신 `MapDefinition` 을 직접 읽기 (ADR 필요).
