# ADR-E02. 저장 포맷은 TOON 이고, 우리 인코더는 **주석을 낸다**

- 상태: 채택 · 2026-09-03 · 사용자 확정 (2026-09-02 "그대로 LLM 프롬프트에 넣는다")
- 관련: SDD-02 §6, 게임 `PLAN-authoring-pipeline.md` §4

## 결정

1. 파일 포맷은 [TOON](https://github.com/toon-format/spec) v4.1 의 **부분집합** (스칼라·중첩 객체·원시 배열·표·주석·인용). 스키마 `pmf.stage/1`.
2. 코덱은 직접 만든다 (TS 와 C# 각각). 공식 SDK 를 쓰지 않는다.
3. 인코더는 `#` 주석 줄을 낸다. 사양은 "인코더는 주석을 내지 않는다" 고 하지만 **의도적으로 어긴다.**
4. 벽 문자는 `W`. 노드 role 에 `-` 를 쓰지 않는다.

## 이유

- **LLM 프롬프트에 그대로 넣는다** 는 요구 때문에 골랐다. JSON 대비 토큰이 눈에 띄게 적다 — 균일 배열을 `[N]{필드}:` 헤더 + 값 행으로 접기 때문이고, 스폰 표·난이도·노드·엣지가 전부 이 모양이다.
- **주석이 된다.** 기획자가 파일 안에 "왜 이 수치인지" 를 남길 수 있고, 툴이 "이 파일은 검증 실패 3건" 같은 것을 파일 머리에 쓸 수 있다. JSON 의 가장 큰 약점이 사라진다.
- 표 헤더의 `N` 이 **행 수를 강제** 한다 — 맵 행이 하나 빠지는 사고를 디코더가 잡는다. CSV 는 못 잡는다.
- 공식 SDK 가 TS 뿐이고, 우리는 부분집합만 쓰므로 직접 구현이 더 작고 C# 과 나란히 둘 수 있다.
- 주석을 내는 편차: 디코더는 사양상 **반드시** 주석을 지우므로, 우리 파일은 여전히 사양 적합 입력이다. 인코더 규칙은 "정규 출력의 단일성" 을 위한 것이고 우리는 정규 출력을 따로 정의한다 (SDD-02 §6-1).
- `#` 벽 금지: 벽으로 시작하는 맵 행이 주석으로 사라진다. `-` role 금지: `-` 로 시작하는 문자열은 인용이 강제된다.

## 대가

- 사양이 Working Draft 라 바뀔 수 있다 → 부분집합만 쓰고, 우리 포맷은 `pmf.stage/N` 으로 따로 버전 관리한다.
- 기획자가 직접 쓴 주석은 툴이 저장할 때 **사라진다** (툴이 낸 주석만 남는다). 툴 상단에 명시한다.
- 파서를 두 언어로 유지한다 → 같은 픽스처를 공유해 어긋남을 잡는다 (SDD-06 §3).

## 되돌리기

`core/toon` 과 `Toon/*.cs` 만 바꾸면 된다. `StageDocument` 는 포맷을 모른다. JSON 으로 가려면 인코더·디코더 교체 + 주석 기능 포기.
