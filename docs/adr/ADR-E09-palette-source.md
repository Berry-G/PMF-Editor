# ADR-E09. 색·크기·수식의 원본은 **게임 코드** 다. 툴은 사본을 갖고 출처를 주석으로 남긴다

- 상태: 채택 · 2026-09-03
- 관련: SDD-01 §5 · SDD-04 §2 · SDD-06 §4 (`palette-source.test.ts`) · SDD-00 §9

## 결정

- `src/core/palette.ts` 의 모든 값은 게임 코드(`SceneParts.cs`, `GreyboxFactory.cs`, `SceneBootstrap.cs`, `PathNodeAuthoring.cs`)에서 복사하고, 각 값 옆에 `// 출처: 파일:라인` 을 단다. 테스트가 주석 존재를 검사한다.
- 시뮬 수식(`core/sim`)도 같다 (`MotherSpawner.cs`, `StageDefinition.cs`, `PathEdge.cs`).
- 색을 `.toon` 파일에 넣지 않는다.

## 이유

- 게임의 타일은 이미지가 아니라 **코드로 만든 단색 사각형** 이다. 색 6개만 옮기면 게임 화면과 같은 그림이 나온다. 에셋 추출이 필요 없다는 행운을 그대로 쓴다.
- 원본이 둘이면 어느 쪽이 최신인지 아무도 모른다. 게임 코드가 원본이고 툴이 사본이면 방향이 하나다.
- 파일에 색을 넣으면 사본이 셋이 된다 (게임 코드 · 타일 에셋 · 파일). 게임 `GetOrCreateTile` 이 매번 코드 값으로 에셋을 덮어쓰므로 파일의 색은 어차피 게임에 반영되지 않는다.
- 출처 주석이 있으면 게임 코드가 바뀌었을 때 **어디를 고쳐야 하는지 grep 한 번** 으로 나온다.

## 대가

- 게임 코드가 바뀌면 툴이 낡는다. 받아들인다 — 반대(툴이 게임을 정의)는 더 나쁘다.
- 색을 데이터로 빼는 것(게임 `PLAN` §9 미결 4)은 열어 둔다. 빼게 되면 게임 쪽이 원본이고 툴은 그 파일을 읽는다 — 이 ADR 의 원칙은 유지된다.

## 되돌리기

색 파일을 도입하면 `palette.ts` 가 그 파일을 로드하는 코드로 바뀐다. 출처 주석은 파일명이 된다.
