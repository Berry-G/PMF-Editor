# ADR-E03. `core/` 는 DOM 을 모른다 — 의존은 `ui→core`, `io→core` 만

- 상태: 채택 · 2026-09-03
- 관련: SDD-01 §2, SDD-06 §4 (`core-purity.test.ts`)

## 결정

`src/core/` (모델·코덱·검증·기하·시뮬·커맨드·팔레트)는 `document`·`window`·`navigator`·`fetch`·`localStorage` 를 참조하지 않고 `ui/`·`io/` 를 import 하지 않는다. 테스트가 이를 검사한다.

## 이유

1. 이 앱에서 **틀리면 안 되는 부분** — 코덱·검증·시뮬 — 이 전부 `core` 다. DOM 이 없으면 vitest 가 브라우저 없이 수 초 안에 전부 덮는다.
2. `core/validate` 와 `core/toon` 은 게임 쪽 C# (`AuthoringValidator`, `ToonReader`) 과 **같은 규칙 ID·같은 픽스처** 를 공유한다. 순수 함수여야 나란히 놓고 비교할 수 있다.
3. 캔버스 렌더는 자주 바뀌고, 문서 모델은 파일 포맷에 묶여 잘 안 바뀐다. 변화 속도가 다른 것을 한 파일에 두면 자주 바뀌는 쪽이 안 바뀌는 쪽을 깨뜨린다.
4. 스택을 바꿔도(ADR-E01 되돌리기) `core` 는 그대로다.

## 대가

- 렌더에 필요한 파생 정보(예: 도달 영역 집합)를 `core` 가 값으로 돌려주고 `ui` 가 그린다 — 한 번 더 감싸는 코드가 생긴다. 감수한다.

## 되돌리기

계층을 무너뜨리는 건 언제든 쉽다. 그래서 테스트로 막는다.
