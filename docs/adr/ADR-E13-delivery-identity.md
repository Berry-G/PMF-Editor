# ADR-E13. 전달본은 내부 이름·대상·검증 상태를 드러낸다

- **날짜:** 2026-09-10
- **상태:** ✅ 확정

## 결정

파일명과 `StageDocument.name` 을 서로 다른 식별자로 화면에 표시한다. Unity 임포터는 파일명이
아니라 내부 이름으로 `<name>.map.asset`, `<name>.path.asset`, `<name>.asset` 세 파일을 만들거나
갱신한다. 내부 이름은 커맨드로 편집하고 파일명은 저장 대상만 바꾼다.

저장·다른 이름 저장·TOON 복사는 현재 문서를 즉시 검증해 같은 전달본을 만든다. 전달 전
요약에는 내부 이름, 파일명, Unity 대상 세 개, 실제 `V` 셀 수, 버스트 트리거 수, 오류·경고·정보
수를 표시한다. 오류 작업본 저장은 계속 허용한다(ADR-E08).

정규 `encode` 는 Unity Exporter와 씨앗의 바이트 동일 비교 기준으로 보존한다. 사용자 저장·복사는
`encodeForDelivery` 를 거쳐 실제 PMF Editor 버전을 한 줄 주석으로 기록하고, 씨앗에만 맞는
2026-09-02 게임 원본 출처 주석은 제거한다. 버전 문자열의 줄바꿈은 공백으로 바꾼다.

캔버스의 마을은 게임 액터 크기 1.4칸을 복사해 그리지 않는다. `V` 한 칸 안쪽에 마커 하나를
그리고 Unity `Village_N` 생성 순서와 같은 번호를 붙인다. 게임 색은 유지한다.

## 왜

파일명만 바꾼 전달본이 기존 내부 이름을 유지하면 Unity에서 뜻밖의 기존 에셋 세 개를 갱신한다.
또 인접한 `V`의 1.4칸 마커가 겹치면 여러 마을이 큰 마을 하나처럼 보인다. 저장 직전의 실제 대상,
개수, 검증 결과를 한 화면에서 확인해야 파일 이름에 `unity-ready`가 붙었다는 이유만으로 준비 완료를
추정하지 않는다.

정규 출력 자체를 바꾸면 게임 C# Writer와 씨앗 바이트 계약까지 동시에 바뀐다. 사용자 전달 경계만
생성 메타데이터를 바꾸면 스키마와 게임 코드를 건드리지 않고 잘못된 출처 주장도 없앨 수 있다.

## 뒤집으려면

내부 이름과 파일명을 자동 동기화하려면 기존 Unity 에셋 갱신과 새 에셋 생성 중 어느 쪽인지 사용자가
먼저 선택할 수 있어야 한다. 정규 헤더를 바꾸려면 TS 골든과 C# Writer의 바이트 비교를 같은 변경으로
갱신해야 한다.
