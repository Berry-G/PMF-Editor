# ADR-E04. 문서는 커맨드로만 바뀐다 — 스트로크당 커맨드 하나

- 상태: 채택 · 2026-09-03
- 관련: SDD-01 §3, SDD-06 §5

## 결정

`StageDocument` 는 `Command { do, undo, coalesceWith? }` 를 통해서만 바뀐다. 커맨드는 새 문서를 돌려준다(in-place 금지). 브러시 드래그·숫자 입력 등 연속 조작은 **코얼레싱** 으로 커맨드 하나가 된다. 히스토리 상한은 두지 않는다.

## 이유

- 스타크래프트급 Undo — 무제한, 라벨 있는 히스토리, 붙여넣기·크기 변경까지 되돌림 — 는 "이전 상태 스냅샷" 으로는 맵이 커질수록 못 버틴다. 커맨드는 바뀐 셀만 기억한다.
- 새 문서를 돌려주면 렌더가 "무엇이 바뀌었나" 를 참조 비교로 안다. 셀 배열은 `Uint8Array` 라 통째 복사가 싸다 (32×18 = 576B).
- 코얼레싱이 없으면 Ctrl+Z 가 셀 하나씩 돌아간다. 그런 Undo 는 아무도 안 쓴다.
- 커맨드는 그 자체로 테스트 단위다: `undo(do(doc)) == doc`.

## 대가

- UI 가 문서를 직접 만지는 지름길이 막힌다. 작은 기능도 커맨드 클래스 하나가 든다. 감수한다 — 지름길 하나가 Undo 를 깨뜨린다.

## 되돌리기

없다. 이 결정을 되돌리는 것은 Undo 를 포기하는 것이다.
