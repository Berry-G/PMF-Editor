# ADR-E05. 마을은 `V` 셀이고, 시작·탈출은 노드 role 이다 — `objects` 섹션은 없다

- 상태: 채택 · 2026-09-03
- 관련: SDD-02 §3, §8 · SDD-03 §5

## 결정

파일에 `objects` 섹션을 두지 않는다.
- 마을 = `map.rows` 의 `V` 셀 그 자체.
- 보호대상 시작 = `role=start` 노드. 모체 시작 = **같은 셀**. 탈출 = `role=exit` 노드.
- "오브젝트 계층" 은 UI 개념이다 (선택·속성 패널). 파일 구조가 아니다.

## 이유

- 게임이 그렇다: `Village` 의 직렬화 필드는 `_hireableUnits` 하나뿐이고 그것도 프리팹 배선이다. 좌표는 `transform` 에서 역산한다 (`Village.cs:34-51`). `Villages[]` 배열 하나가 타일과 프리팹 위치를 동시에 결정한다 (`SceneParts.BuildActors`).
- 모체가 보호대상과 같은 곳에서 출발하는 것은 **설계 의도** 다: "추격자는 같은 시작점에서 출발해야 뒤쫓아오는 그림이 된다" (`GreyboxMapData.cs:64-65`). 따로 둘 이유가 없다.
- 같은 사실을 두 곳(셀 + 오브젝트 목록)에 적으면 검증 규칙이 하나 더 필요하고, LLM 이나 사람이 한쪽만 고치는 실수가 생긴다.
- YAGNI: 마을에 저작 속성(고용 병종·재고·쿨다운 — GDD §9 가 언젠가 둘 것들)이 생기면 그때 `villages[N]{x,y,...}` 를 추가하고 `V` 를 파생으로 바꾼다. 스키마 버전을 올리면 된다.

## 대가

- 마을 하나를 "옮기는" 조작이 UI 에서는 셀 두 개(옛 것 지우기 + 새 것 칠하기)로 구현된다 — 커맨드 하나로 감싼다.
- 모체 시작을 따로 실험하고 싶으면 스키마를 올려야 한다.

## 되돌리기

`pmf.stage/2` 에서 `villages` 표 추가. 변환기는 `V` 셀을 표로 옮기면 된다 — 정보 손실 없음.
