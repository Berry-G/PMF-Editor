# ADR-E12. 우클릭은 컨텍스트 메뉴다 — 지우개를 폐지한다

- **날짜:** 2026-09-06
- **상태:** ✅ 확정 (ADR 없이 SDD-03 §2 에 있던 "우클릭 = 지우개" 를 뒤집는다)

## 결정

캔버스 우클릭은 **도구와 무관하게** 컨텍스트 메뉴를 연다.
칠하는 도구의 "우클릭 = 지우개 셀" 을 없앤다. `eraserCell` 은 남지만 이제
**`Delete`(선택 영역 지우기)에서만** 쓰인다.

## 왜

사용자 판단이다 (2026-09-06):

> 지우기 동작 자체가 불필요하다고 생각함. 빈칸을 선택하고 칠해버려야하는부분이지
> 지우기 동작은 필요없음.

맞는 말이다. 팔레트에 칸 7종이 다 있으므로 "지우기" 는 **다른 칸으로 덧칠하기** 와 같은
일이다. 같은 결과를 내는 조작을 둘 두면 배울 것만 늘고, 그중 하나(우클릭)는 화면에
아무 단서가 없었다.

그리고 그 자리를 컨텍스트 메뉴가 훨씬 잘 쓴다. 노드·엣지 편집이 "도구 고르기 → 클릭 →
오른쪽 패널" 세 단계라 처음 쓰는 사람이 무엇이 되는지 알 수 없었는데, 대상 위에서 바로
우클릭하면 할 수 있는 일이 보인다.

## 왜 도구별로 나누지 않는가

처음에는 경로 도구(N E V)에서만 메뉴를 열고 셀 도구에서는 지우개를 남겼다. 그러자
**같은 우클릭이 도구에 따라 다르게 돌았고, 화면에는 지금 무슨 도구인지 표시가 없었다.**
사용자가 바로 걸렸다 — "우클릭이 지우기로 동작하고있어. 컨텍스트는 안뜬다".

메뉴 내용은 **커서 아래에 무엇이 있느냐로만** 정한다. 도구 상태를 섞지 않는다.

## 남는 것

- `Delete` 는 그대로 `eraserCell`(기본 `Buildable`)로 선택 영역을 칠한다.
- 스포이드 우클릭으로 `eraserCell` 을 바꾸던 길은 사라졌다. 지금은 기본값 고정이다.
  바꿀 필요가 생기면 팔레트 쪽에 표시가 보이는 UI 로 다시 넣는다 — 숨은 조작으로 되돌리지 마라.

## 뒤집으려면

우클릭 지우개를 되살리려면 컨텍스트 메뉴를 어디로 옮길지 먼저 정해야 한다. 둘은 같은
입력을 놓고 경쟁한다. 도구별 분기는 이미 한 번 실패했다(위).
